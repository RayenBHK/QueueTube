# Track the QueueTube documentation plan

This plan defines the goal, audience, coverage, and open publication decisions for QueueTube's documentation set.

## Goal

Help a new QueueTube user install, operate, verify, and evaluate the extension without reading its source code.

## Audience

The primary audience wants a calmer YouTube workflow and may not write code. Contributors and Chrome Web Store reviewers form the secondary audience.

## Content plan

| Page | Type | Job |
| --- | --- | --- |
| `README.md` | Landing | Explain the product and route readers to the right task |
| `docs/TESTING.md` | How-to | Verify one release from logic through browser behavior |
| `docs/ACCESSIBILITY.md` | Reference | Describe keyboard, screen-reader, visual, and verification support |
| `CONTRIBUTING.md` | How-to | Prepare and submit a safe code change |
| `ARCHITECTURE.md` | Reference | Describe components, state, permissions, and failure behavior |
| `PRIVACY.md` | Conceptual | Explain the data QueueTube handles and retains |
| `SECURITY.md` | How-to | Route vulnerability reports to a private channel |
| `CHANGELOG.md` | Reference | Record user-facing release changes |
| `CHROMEWEBSTORE.md` | Reference | Hold copy-ready store metadata and submission status |

## Open publication decisions

Before Chrome Web Store submission, the publisher must supply a monitored public contact email and confirm the final distribution regions.
